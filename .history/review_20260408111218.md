## 3. Đánh giá chi tiết các file chính

### app.py
Ưu điểm:
- Cấu trúc rõ ràng, có phần import, config, khởi tạo dịch vụ, route và shutdown.
- Dùng Flask để tạo giao diện web và API.
- Có class `Config` để gom đường dẫn và thông số chung.
- Khởi tạo đủ các thành phần: camera, UART, Ethernet, YOLO, CNN, tiền xử lý ảnh.
- Có gọi `atexit.register` để tắt camera khi tắt server.
- Hỗ trợ streaming camera qua `/camera_stream`.

Nhược điểm:
- `sys.path.append(CURRENT_DIR)` không cần thiết, dễ gây xung đột import.
- Đường dẫn model dùng string relative, dễ lỗi khi chạy từ thư mục khác.
- Khởi tạo camera, UART, Ethernet, model khi import file gây side effect và khó test.
- Thực thi toàn bộ dịch vụ ngay khi import khiến `app` không phù hợp WSGI/pytest.
- Thiếu try/except khi load model, mở camera, kết nối UART/Ethernet.
- Route `/camera_stream` có vòng lặp vô hạn nhưng không kiểm tra trạng thái camera, dễ treo.
- Route `/camera_capture` gọi `engine.thuc_thi_AI()` nhưng không bắt lỗi, không validate kết quả.
- Chưa có cấu trúc `create_app()` để tách app factory, dễ gây khó khăn khi mở rộng.
- Có khả năng block request nếu `engine.thuc_thi_AI()` chạy lâu.

Gợi ý:
- Khởi tạo dịch vụ trong hàm `create_app()` hoặc `init_services()`.
- Dùng `os.path.join(CURRENT_DIR, ...)` cho tất cả đường dẫn.
- Thêm xử lý lỗi và trả JSON báo lỗi rõ ràng.
- Cấu hình port UART/IP Ethernet qua biến môi trường.

### camera.py
Ưu điểm:
- Tách riêng phần lấy luồng camera khỏi `app.py`.
- Nếu có class `Camera` với `start()`, `read()`, `stop()`, thiết kế này hợp lý.
- Giúp phần web app không cần quản lý trực tiếp thao tác OpenCV.

Nhược điểm:
- Nếu `Camera` mở camera khi import module thì vẫn gây side effect.
- Cần đảm bảo xử lý khi camera không mở được, mất kết nối hoặc đóng đột ngột.
- Cần release tài nguyên chắc chắn khi dừng, tránh treo thiết bị.
- Cần kiểm tra thread-safety nếu dùng luồng riêng.
- Nếu `read()` trả `False`, nên xử lý lại thay vì chỉ bỏ qua.

Gợi ý:
- Kiểm tra `cam.is_open()` sau `start()`.
- Thêm timeout / fallback nếu camera bị mất.
- Trả lỗi hoặc status rõ ràng khi `read()` không thành công.

### cnn.py
Ưu điểm:
- Tách wrapper logic CNN ra module riêng, giúp app gọn.
- Nếu `Simple_CNN_config` gom model, transform, device và classes thì dễ quản lý.
- Giúp client gọi inference mà không cần biết chi tiết model.

Nhược điểm:
- Cần đảm bảo device và transform khớp với lúc huấn luyện.
- Nếu `Simple_CNN_config` không kiểm tra `None` hoặc lỗi model, app dễ crash.
- Cần xử lý ngoại lệ khi predict / load weights.
- Nên kiểm tra đầu vào trước khi cho vào model.

Gợi ý:
- Thêm xác thực ảnh trước khi infer.
- Sử dụng `torch.no_grad()` trong inference.
- Nếu load model thất bại, trả về lỗi rõ ràng.
- Xử lý fallback khi model hoặc device không khả dụng.

### ethernet.py
Ưu điểm:
- Tách dịch vụ TCP/IP ra module riêng, phù hợp hệ thống nhiều trạm.
- Giúp `app.py` gọn và dễ theo dõi logic giao tiếp.

Nhược điểm:
- Cần quản lý timeout, reconnect và lỗi mạng.
- Nếu socket blocking, có thể ảnh hưởng tới luồng chính.
- Cần rõ format dữ liệu gửi/nhận, hiển thị kiểu message.
- Cần hỗ trợ cấu hình IP/port linh hoạt.

Gợi ý:
- Thêm timeout và retry khi kết nối thất bại.
- Tách thread hoặc async cho nhận dữ liệu.
- Đảm bảo format dữ liệu/serialization nhất quán.
- Đưa địa chỉ IP, cổng vào config hoặc env var.

### logic_2.py
Ưu điểm:
- Nơi gom logic điều phối giữa YOLO, CNN, UART, Ethernet.
- Giúp `app.py` chỉ gọi `engine.thuc_thi_AI()` và không cần biết chi tiết.
- Nếu thiết kế đúng, có thể tái sử dụng nhiều lần.

Nhược điểm:
- Dễ trở nên quá nặng nếu cùng lúc chịu nhiệm vụ AI + IO + giao tiếp.
- Cần tách rõ `AI inference` và `hardware communication`.
- Cần kiểm tra thread-safety nếu dùng trong callback UART và request web song song.
- Nếu `TrafficLogic` chứa nhiều trạng thái nội bộ, có thể gây race condition.
- Không rõ cách xử lý lỗi khi một phần dịch vụ không sẵn sàng.

Gợi ý:
- Tách `TrafficLogic` thành các bước nhỏ: lấy ảnh, tiền xử lý, YOLO/CNN, gửi lệnh, cập nhật trạng thái.
- Thêm logging và return status/error.
- Không trực tiếp thực hiện IO nặng trong cùng hàm xử lý request.

### tienxulyanh.py
Ưu điểm:
- Tách tiền xử lý ảnh ra module độc lập.
- Nếu module này xử lý resize, normalize, SCI thì phù hợp.
- Giúp giữ `app.py` và `logic` sạch hơn.

Nhược điểm:
- Cần đảm bảo xử lý đúng kích thước và loại ảnh cho các model.
- Nếu `sci_path` thiếu, có thể crash ngay khi khởi tạo.
- Cần kiểm tra mọi đầu vào trước khi chuyển vào mô hình SCI hoặc YOLO.
- Chưa rõ mức độ tương thích giữa tiền xử lý và model YOLO/CNN.

Gợi ý:
- Thêm xác thực ảnh đầu vào (`None`, kích thước, format).
- Nếu dùng SCI, cho phép disable khi không cần.
- Trả thông tin rõ ràng về lỗi tiền xử lý.
- Tách preprocessing cho YOLO và CNN nếu khác nhau.

### uart_service.py
Ưu điểm:
- Tách giao tiếp UART/Serial ra module riêng.
- Giúp rõ trách nhiệm gửi/nhận dữ liệu từ ESP32.

Nhược điểm:
- Cần cấu hình port qua env/config, không hardcode `/dev/ttyAMA0`.
- Trên Windows port này không dùng được, nên cần giải pháp cross-platform hoặc mock.
- Cần xử lý lỗi khi cổng không mở hoặc bị ngắt.
- Cần đảm bảo thao tác đọc/ghi không block và không gây treo app.

Gợi ý:
- Thêm kiểm tra open port thành công.
- Xử lý reconnect khi cổng bị mất.
- Nếu dùng callback, cần thread-safe và tránh crash khi dữ liệu xấu.
- Log đầy đủ trạng thái UART.

### yolov26.py
Ưu điểm:
- Wrapper YOLO giúp tách nhận diện khỏi app chính.
- Nếu lọc class và tiền xử lý đúng thì rất phù hợp.
- Giúp dễ thay đổi model YOLO mà không cần chỉnh `app.py`.

Nhược điểm:
- Cần xử lý lỗi load model khi file weight không tồn tại.
- Nếu dùng Ultralytics YOLO, cần cấu hình threshold và NMS rõ.
- Cần chuẩn hóa đầu vào trước khi infer.
- Cần output định dạng rõ ràng, tránh trả object nội bộ phức tạp cho app.

Gợi ý:
- Kiểm tra existence của file model khi load.
- Thêm cấu hình confidence threshold, device, image size.
- Tách logic infer và hậu xử lý (lọc class, bounding box).
- Trả về data đơn giản, dễ dùng cho `TrafficLogic`.

- Cần chuẩn hóa đầu vào trước khi infer.
- Cần output định dạng rõ ràng, tránh trả object nội bộ phức tạp cho app.

Gợi ý:
- Kiểm tra existence của file model khi load.
- Thêm cấu hình confidence threshold, device, image size.
- Tách logic infer và hậu xử lý (lọc class, bounding box).
- Trả về data đơn giản, dễ dùng cho `TrafficLogic`.
