# Review dự án Traffic_Control

## 1. Tổng quan

Đã xem xét cấu trúc thư mục `web_test` và các file trong đó. Bài đánh giá này tập trung vào:
- `app.py`
- các module AI và phần cứng
- các file web frontend
- các file mô hình và tiền xử lý

Mục tiêu:
- chỉ ra ưu điểm cho từng file
- chỉ ra nhược điểm hiện tại
- đưa ra gợi ý cải thiện cụ thể

---

## 2. Cấu trúc thư mục `web_test`

- app.py
- camera.py
- cnn.py
- ethernet.py

- model_sci.py
- tienxulyanh.py

## 3. Đánh giá chi tiết từng file

### app.py
Ưu điểm:
- Có cấu trúc rõ ràng, chia phần import, config, khởi tạo dịch vụ, route và shutdown.
- Dùng Flask để xây dựng giao diện web và API.
- Có lớp `Config` gom cấu hình chung, thuận tiện chỉnh sửa.
- Khởi tạo đầy đủ các thành phần: camera, UART, Ethernet, YOLO, CNN, tiền xử lý.
- Có cơ chế dừng camera bằng `atexit`.
- Hỗ trợ streaming camera qua route `/camera_stream`.

Nhược điểm:
- Dùng `sys.path.append(CURRENT_DIR)` không cần thiết.
- Các đường dẫn model hardcode relative, dễ lỗi khi chạy từ thư mục khác.
- Khởi tạo phần cứng và model khi import file gây side effect.
- Thiếu xử lý lỗi khi mở camera, kết nối UART/Ethernet, hoặc load model.
- Route `camera_stream` có vòng lặp vô hạn nhưng không kiểm tra trạng thái camera.
- Thiếu factory `create_app()` cho WSGI hoặc test.
- Khá ít validation khi `engine.thuc_thi_AI()` trả kết quả.

### camera.py
Ưu điểm:
- Tách riêng phần lấy luồng camera khỏi `app.py`.
- Nếu có class `Camera` với `start()`, `read()`, `stop()` thì đúng hướng.

Nhược điểm:
- Cần đảm bảo không mở camera ngay khi import.
- Cần xử lý trường hợp camera không khởi động được hoặc mất kết nối.
- Cần release tài nguyên chắc chắn khi dừng.

### cnn.py
Ưu điểm:
- Tách wrapper logic CNN thành module riêng.
- Giúp app giảm bớt phụ thuộc trực tiếp vào model và transform.

Nhược điểm:
- Cần đảm bảo cấu hình device/transform nhất quán.
- Nên kiểm tra input và xử lý ngoại lệ khi dự đoán.
- Nhiều khả năng thiếu cách xử lý fallback khi model tải không được.

### ethernet.py
Ưu điểm:
- Tách dịch vụ giao tiếp TCP/IP ra module riêng.
- Hữu ích khi mở rộng hệ thống nhiều trạm.

Nhược điểm:
- Cần thêm xử lý timeout, reconnect, lỗi mạng.
- Nên thiết kế rõ format dữ liệu gửi/nhận.
- Cần cấu hình IP/port linh hoạt thay vì cố định.

### logic_2.py
Ưu điểm:
- Tập trung logic điều phối giữa YOLO, CNN, UART, Ethernet.
- Giúp `app.py` gọn hơn và dễ bảo trì nếu logic đủ rõ ràng.

Nhược điểm:
- Nếu quá nhiều trách nhiệm sẽ khó mở rộng.
- Cần tách biệt logic xử lý ảnh và logic giao tiếp.
- Cần kiểm tra thread-safety khi nhiều request cùng chạy.

### loss_sci.py
Ưu điểm:
- Có khả năng chứa loss function cho SCI hoặc việc huấn luyện.
- Tách riêng chức năng này giúp dễ bảo trì.

Nhược điểm:
- Nếu dùng cho inference thì cần rõ vai trò.
- Cần comment hoặc tài liệu về cách sử dụng.

### model_sci.py
Ưu điểm:
- Tách phần mô hình SCI riêng.
- Giúp dự án rõ ràng hơn nếu giữ nhiều loại mô hình.

Nhược điểm:
- Cần kiểm tra xem model có load đúng và tương thích với phần tiền xử lý.
- Nếu chỉ dùng inference thì nên tách rõ mô hình và weight.

### tienxulyanh.py
Ưu điểm:
- Tách tiền xử lý ảnh ra module độc lập.
- Giúp chuẩn hóa đầu vào trước khi vào YOLO/CNN.

Nhược điểm:
- Cần đảm bảo xử lý đúng định dạng ảnh và kích thước.
- Cần thêm kiểm tra khi file SCI bị thiếu hoặc không load.

### uart_service.py
Ưu điểm:
- Tách giao tiếp UART/Serial ra module riêng.
- Làm rõ chức năng gửi/nhận dữ liệu từ ESP32.

Nhược điểm:
- Cần cấu hình port thông qua environment hoặc config.
- Chưa rõ xử lý lỗi khi cổng không mở được.
- Trên Windows port `/dev/ttyAMA0` không dùng được.

### yolov26.py
Ưu điểm:
- Wrapper YOLO giúp tách nhận diện khỏi app chính.
- Có thể xử lý class filtering và tiền xử lý riêng.

Nhược điểm:
- Cần xác thực đầu vào/đầu ra YOLO.
- Nên xử lý tình huống model không load được hay dự đoán trả về lỗi.
- Cần cài đặt threshold, NMS rõ ràng.

### SimpleCNN/custom.py
Ưu điểm:
- Chứa cấu trúc mạng CNN riêng, dễ quản lý.
- Phù hợp cho training và inference.
- Rõ ràng nếu module này được dùng chung cho nhiều project.

Nhược điểm:
- Cần comment rõ từng lớp mạng.
- Cần kiểm tra khớp với weights `best_cnn_model.pth`.
- Cần đảm bảo `eval()` và `to(device)` được dùng đúng.

### SimpleCNN/dataset_custom.py
Ưu điểm:
- Nếu chứa dataset custom, giúp chuẩn hóa dữ liệu khi huấn luyện.
- Tách logic dataset ra module sạch.

Nhược điểm:
- Cần kiểm tra xử lý augmentation và định dạng label.
- Nên hỗ trợ đường dẫn và cấu hình linh hoạt.

### SimpleCNN/train_custom.py
Ưu điểm:
- Có script training riêng, dễ tái sử dụng.
- Giúp tách giai đoạn huấn luyện khỏi inference.

Nhược điểm:
- Cần bảo đảm training script không ảnh hưởng tới app production.
- Nên cấu hình rõ learning rate, checkpoint, resume.

### static/script.js
Ưu điểm:
- Tách logic frontend ra file riêng.
- Giúp code web sạch và dễ quản lý.

Nhược điểm:
- Cần kiểm tra tương tác với API `/camera_capture` và `/camera_stream`.
- Nên xử lý lỗi network và feedback cho người dùng.

### static/style.css
Ưu điểm:
- Có styling tách riêng, giúp giao diện đẹp hơn.
- Nếu có layout rõ, phục vụ hiển thị camera/ kết quả tốt.

Nhược điểm:
- Cần đảm bảo responsive và hiển thị đúng trên nhiều màn hình.
- Chưa rõ có phần hiển thị trạng thái kết nối hay chưa.

### templates/index.html
Ưu điểm:
- Có frontend giao diện cơ bản.
- Hỗ trợ render `class_names` từ Flask.

Nhược điểm:
- Cần kiểm tra nếu template thiếu `csrf` hoặc không có xử lý lỗi.
- Cần xác định rõ UI hiển thị kết quả AI và trạng thái hệ thống.

### weights/difficult.pt, easy.pt, medium.pt
Ưu điểm:
- Có nhiều trọng số SCI khác nhau, phù hợp thử nghiệm.

Nhược điểm:
- Cần xác định file nào dùng cho mục đích nào.
- Nên đặt cùng với cấu hình rõ ràng trong `Config` nếu dùng.

- Không rõ cơ chế test/kiểm thử.

## 5. Gợi ý cải thiện

- Viết `create_app()` và `init_services()` trong `app.py`.
- Dùng `os.path.join(CURRENT_DIR, ...)` cho tất cả đường dẫn.
- Tách phần khởi tạo phần cứng/model ra khỏi import time.
- Thêm try/except khi mở camera, load model, kết nối UART/Ethernet.
- Cấu hình port, IP, device qua biến môi trường.
- Tạo logging và trả lỗi rõ ràng từ API.
- Tách rõ `TrafficLogic` thành:
  - lấy ảnh
  - xử lý YOLO/CNN
  - gửi UART/Ethernet
  - trả kết quả cho frontend
- Kiểm tra `static/script.js` để xử lý lỗi khi API không trả đúng.
- Xác thực `templates/index.html` có hiển thị trạng thái hệ thống.
- Nếu cần, thêm unit test cho `camera.py`, `uart_service.py`, `yolov26.py`, `cnn.py`, `logic_2.py`.

- Thiếu xử lý ngoại lệ và fallback khi phần cứng/mô hình lỗi.
- Thiếu config linh hoạt cho OTA, môi trường dev/prod.
- Cần tách rõ hơn logic `TrafficLogic` và luồng xử lý ảnh.
- Không rõ cơ chế test/kiểm thử.
- Cần cập nhật phần frontend để hiển thị lỗi và trạng thái.

## 5. Gợi ý cải thiện

- Viết `create_app()` và `init_services()` trong `app.py`.
- Dùng `os.path.join(CURRENT_DIR, ...)` cho tất cả đường dẫn.
- Tách phần khởi tạo phần cứng/model ra khỏi import time.
- Thêm try/except khi mở camera, load model, kết nối UART/Ethernet.
- Cấu hình port, IP, device qua biến môi trường.
- Tạo logging và trả lỗi rõ ràng từ API.
- Tách rõ `TrafficLogic` thành:
  - lấy ảnh
  - xử lý YOLO/CNN
  - gửi UART/Ethernet
  - trả kết quả cho frontend
- Kiểm tra `static/script.js` để xử lý lỗi khi API không trả đúng.
- Xác thực `templates/index.html` có hiển thị trạng thái hệ thống.
- Nếu cần, thêm unit test cho `camera.py`, `uart_service.py`, `yolov26.py`, `cnn.py`, `logic_2.py`.
